Payment (FR4)

PaymentGateway interface
↳ MockPaymentGateway (simulated, PayFast-style)
4242 4242 4242 4242 → approved
4000 0000 0000 0002 → declined (402)

OrderService only knows the interface, so a real gateway could replace the mock without changing it. Card numbers are never stored.

Errors (one format)

GlobalExceptionHandler turns every failure into JSON:
{timestamp, status, error,
 message, path, fieldErrors?}

400 · 401 · 402 · 403 · 404 · 409 — the UI shows the message, never a stack trace.

Race condition

Two buyers pay for one listing: SELECT … FOR UPDATE makes the second wait, re-check, and get 409. Proven by a two-thread test.

Scope

BUILT FR1–FR6, NFR1 security, NFR3 mobile-first
NOT BUILT Redis cache (NFR2a), separate payment service (NFR2c), messaging, notifications, real PayFast

Optional deployment

Vercel (React build) → Render (API in Docker, prod profile) → Aiven (MySQL). Secrets only in environment variables. Marking runs locally.
